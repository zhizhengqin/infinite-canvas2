# DreamMaker 本机账号登录与自动续期

当前入口：http://127.0.0.1:23210/dreammaker/settings。点登录后在独立官方Chrome窗口输入账号密码并完成必要验证。窗口由本机代理单独创建；成功接收OAuth访问及刷新令牌、校验账号后自动关闭，不接管用户现有Chrome窗口。

账号会话写入~/.infinite-canvas/dreammaker-account/session.enc，AES-256-GCM加密；vault.key和密文权限0600，目录0700。密钥与密文同属当前系统用户，防配置误导出，不提供对同一系统用户的隔离。不会保存账号密码。独立Chrome登录资料目录保留官方登录状态，访问权限属于当前用户。

现有3001画布与同账号旧Bearer匹配时代理自动使用已登录会话；旧Bearer仅用于同账号选择，代理授权令牌不回传前端。仅允许localhost/127.0.0.1的3001画布与23210设置页使用账号操作。其他来源、其他账号与非官方API禁止借用会话。以后新部署前端可直接选择账号登录模式，无需API Key。

访问令牌按实际exp判断到期，按官方OAuth接口刷新；并发共用一次续期，轮换结果原子写入。刷新失败不自动重试、不重新登录账号、不重新提交生成；需要人机验证或官方撤销会话时用户重新登录。刷新周期不是永久有效承诺。

设置页“验证自动续期”执行一次真实刷新并只返回连接状态；画布生成需按电影项目授权另行执行，不能以测试续期提交付费视频。

验证：node --test canvas-proxy/dreammaker-auth.test.js，十项通过。用户已完成官方登录，真实刷新两次200、服务重启恢复、旧画布已过期配置查询同账号与原任务200均已验证。未构建/切换原Docker镜像，不夹带工作区未发布变更。

回退：本次改前文件保存在/tmp/canvas-dreammaker-auth-backup，保留所有原有用户改动。恢复其中对应文件、移除本次新文件并重启com.basketikun.canvas-proxy即可恢复原代理行为；不删除账号会话或影片数据。不要把整仓git reset当作回退。

真实接入修复补记：官方浏览器v2刷新还携带__Host-auth_session统一登录Cookie，必须与刷新令牌一起加密保存并在刷新时发送。只保存refresh_token的初版真实验证失败，已按官方协议补齐；已登录的专用profile可重新接入，无需重新输入密码。自然到期长任务待使用反馈，不声称会话永久有效。
